1. Introduction                                                 *nota-intro*

Review with the `nota` CLI from Vim or Neovim. Start or select a review,
read its notes and suggestion patches, and write notes without leaving the
editor. Review storage and validation belong to Nota.

Requirements:
  - Vim 8.2+ or Neovim
  - Git
  - `nota` on your PATH, or |g:nota_executable| set

CLI calls run synchronously.

==============================================================================
2. Installation                                               *nota-install*

Build the CLI from the Verka repository: >sh
        cargo build -p nota
<
or install it: >sh
        cargo install --path nota
<
Add `nota-vim/` to your plugin manager or Vim's runtime path: >vim
        set runtimepath+=/path/to/verka/nota-vim
<
Generate the help tags so |:help| can find this file: >vim
        :helptags /path/to/verka/nota-vim/doc
<

3. Usage                                                        *nota-usage*

A typical review: >vim
        :NotaStart HEAD nota/my-review
        :NotaNote Please explain the error handling.
        :10,15NotaNote This needs a regression test.
        :NotaNote
<
Starting a review and adding notes leave your checkout and index untouched.

                                                            *nota-selection*
Each worktree has a selected review, set by |:NotaStart|, |:NotaShow|, and
|:NotaBranch|. With no selection, commands use the checked-out branch, as
the CLI does. Selections are independent per worktree and last until Vim
exits.

Commands find the worktree from the current file, or from Vim's working
directory in a buffer without a file. Review, entry, and note buffers carry
their own repository and branch context.

==============================================================================
4. Commands                                                  *nota-commands*

:NotaStart [revision] [branch]                                  *:NotaStart*
        Start a review of [revision] (default: HEAD) on [branch] (default:
        a generated name), open it, and select it for this worktree. The
        review branch is created without changing the checkout or index.

:NotaShow [branch]                                              *:NotaShow*
        Open the review on [branch] and select it. Without [branch], use the
        |nota-selection| for this worktree. See |nota-mappings| for the keys
        available in the review buffer.

:NotaBranch [branch]                                            *:NotaBranch*
        Select the existing review on [branch] without opening it. Without
        [branch], clear the selection so commands use the checked-out
        branch again.

:NotaQuickfix [branch]                                      *:NotaQuickfix*
        Fill the quickfix list with the entries of the review on [branch],
        or of the |nota-selection|, in review order, and open it. See
        |nota-quickfix|.

:NotaInline                                                  *:NotaInline*
        Neovim only. Turn the inline display of the selected review's
        suggestions in source buffers on or off. See |nota-inline|.

:[range]NotaNote [text]                                         *:NotaNote*
        Append [text] as a note to the selected review. Without [text], open
        an editable Markdown draft. With [range], record the source lines.
        See |nota-notes|.

:NotaSuggest [text]                                          *:NotaSuggest*
        Commit this worktree's uncommitted edits to the selected review as a
        suggestion, with [text] as its comment, and undo them in the
        checkout. Without [text], open an editable Markdown draft. Fails
        when no review is selected. See |nota-suggest|.

==============================================================================
5. Mappings                                                  *nota-mappings*

The review buffer opened by |:NotaShow| and |:NotaStart| defines:

  <CR>          Open the subject or the entry under the cursor, showing its
                full commit message and patch.
  gq            Fill the quickfix list, as |:NotaQuickfix|.
  r             Refresh the review. Use after recording notes or committing
                suggestions.
  n             Compose a note, as |:NotaNote| without arguments.
  s             Compose a suggestion, as |:NotaSuggest| without arguments.
  q             Close the buffer.

Entry buffers also map `q` to close.

==============================================================================
6. Notes                                                        *nota-notes*

`:NotaNote {text}` submits the rest of the command line as a note.

                                                              *nota-draft*
`:NotaNote` with no text opens an editable Markdown draft. |:write| submits
it and closes the draft; `:bdelete!` discards it. Failed submissions
preserve the draft. Hidden drafts can be recovered with `:buffers!` and
`:buffer {number}`. Each draft keeps the branch it was opened for, even if
you select another review later.

                                                              *nota-source*
A range such as `:'<,'>NotaNote` appends `Source: path:10-15` to the
submitted note. Paths are relative to the worktree and line numbers refer to
the buffer at the time you run the command; this is prose context, not a
structured location tracked by Nota. Plain `:NotaNote` writes a general
note. A draft pins its range when opened.

                                                            *nota-quickfix*
|:NotaQuickfix| lists each note at its |nota-source| lines, and each
suggestion once per changed hunk, so |:cnext| and |:cprevious| step through
everything the review points at. Notes without a source are listed without
a location; |:cnext| skips them. Items are labelled with their kind and
commit: >
        file.txt|1| [note 227bb165] Explain these lines.
        file.txt|3| [suggestion 7c071a3e] Shout the last line.
<
Locations open files in this worktree, but their line numbers refer to the
review: a note to the buffer it was written in, a suggestion to the file as
its commit leaves it. They match your checkout while it is at the subject and
the review's earlier suggestions do not shift those lines.

==============================================================================
7. Suggestions                                            *nota-suggestions*

Nota represents suggestions as ordinary Git commits on the review branch.

                                                            *nota-suggest*
The quick way is to edit files in your own checkout and run: >vim
        :NotaSuggest Handle the missing value explicitly.
<
This moves your uncommitted edits to tracked files (staged or not) onto
the review selected with |:NotaStart|, |:NotaShow|, or |:NotaBranch|, without
falling back to the checked-out branch. The edits are merged onto the review
as a patch against your HEAD, so they keep the review's earlier changes and
suggestions. Once committed, the edited files are reset to HEAD in your
checkout and index, and their buffers reloaded: the edits now live in the
review, and the next |:NotaSuggest| holds only what you edit after it.
Untracked files are not included; write modified buffers first. Nota
refuses edits that conflict with the review, including changes on lines
next to ones the review changed, and refuses when the review branch is
checked out in this worktree; commit there with Git instead. Without text,
|:NotaSuggest| opens a draft like |nota-draft|; the edits are taken when you
|:write| it.

Alternatively, create a separate worktree, edit there, and commit: >sh
        git worktree add ../my-review nota/my-review
        git -C ../my-review add src/example.rs
        git -C ../my-review commit -m 'Handle the missing value explicitly'
<
The commit appears as a suggestion in |:NotaShow| after a refresh. Accepted
suggestions are cherry-picked individually onto the destination branch.
Published reviews are append-only; do not amend, rebase, or force-push their
commits. See `nota/PROTOTYPE_V1.md` in the Verka repository.

8. Inline review (Neovim)                                      *nota-inline*

|:NotaInline| marks each hunk of the review's suggestions in the buffers of
the files it changes, for the review selected in that worktree or else the
checked-out review branch, as other commands do. Each hunk gets a sign on
the lines it covers and its commit and summary at the end of its first line:
>
    3     value.unwrap() ✎ 9c4c67c4 Handle the missing value explicitly
<
Expanded, a hunk also shows the change itself: the lines it removes are
highlighted, and the lines it adds appear as virtual lines below them. The
buffer text is never changed.

Hunk lines refer to the file as the suggestion's parent commit had it, so
they are mapped onto the buffer by diffing that version against the buffer
text, including unsaved edits. Each hunk is then shown as one of:

  pending       The lines the hunk replaces are in the buffer, as in your
                own checkout after |:NotaSuggest|.
  applied       The lines it suggests are in the buffer, as in a worktree of
                the review branch. Expanded, the lines it removed appear as
                virtual lines above.
  stale         Neither: the buffer changed those lines. The hunk is shown
                near where it was, with `(stale)` after its summary;
                expanded, it shows the hunk as a small diff.

Notes are not shown inline; use |:NotaQuickfix|.

The display follows selections, |:NotaSuggest|, and refreshes in the review
buffer, and is redrawn when a buffer is shown, read, written, or changed in
Normal mode. Commits made outside Vim are picked up the next time a buffer
is shown.

                                                       *nota-inline-mappings*
Buffers with review items define:

  ]r            Go to the [count]th next review item.
  [r            Go to the [count]th previous review item.
  <Leader>re    Expand or collapse the item under the cursor.
  <Leader>rE    Expand every item in the buffer, or collapse them all when
                all are expanded.

                                                     *nota-inline-highlights*
Highlight groups, linked by default:

  NotaInlineSign        Sign of a pending hunk (|hl-DiagnosticInfo|).
  NotaInlineApplied     Sign of an applied hunk (DiagnosticOk).
  NotaInlineStale       Sign of a stale hunk (|hl-Comment|).
  NotaInlineSummary     Commit and summary (DiagnosticVirtualTextInfo).
  NotaInlineAdd         Added lines (|hl-DiffAdd|).
  NotaInlineDelete      Removed lines (|hl-DiffDelete|).

9. Configuration                                               *nota-config*

                                                         *g:nota_executable*
g:nota_executable       string (default: 'nota')
        Path to the Nota CLI, without arguments. Use it when the CLI is not
        on your PATH: >vim
                let g:nota_executable = '/path/to/verka/target/debug/nota'
<
                                                    *g:nota_inline_expanded*
g:nota_inline_expanded  number (default: 0)
        When 1, |nota-inline| hunks start expanded.

                                                    *g:nota_inline_mappings*
g:nota_inline_mappings  number (default: 1)
        When 0, |nota-inline-mappings| are not defined. The functions are
        available to map yourself: >lua
                local inline = require('nota.inline')
                vim.keymap.set('n', ']r',
                  function() inline.jump(vim.v.count1) end)
                vim.keymap.set('n', '[r',
                  function() inline.jump(-vim.v.count1) end)
                vim.keymap.set('n', '<Leader>re', inline.toggle_item)
                vim.keymap.set('n', '<Leader>rE', inline.toggle_all)
<

10. Testing                                                   *nota-testing*

The integration test uses the real CLI and disposable Git worktrees. From
the repository root: >sh
        cargo build -p nota
        vim -Nu NONE -n -es -S nota-vim/tests/integration.vim
        nvim --headless -u NONE -n -S nota-vim/tests/integration.vim
        nvim --headless -u NONE -n -S nota-vim/tests/inline.vim
<
Set `$NOTA_TEST_EXECUTABLE` to test a different CLI binary.
